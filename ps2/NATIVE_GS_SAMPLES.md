# Box3D PS2 visual sample bring-up: native GS + GIF

Run `sh ps2/build_ee.sh` with PS2DEV and PS2SDK installed. Start
`ps2/box3d_ps2_samples.elf` in PCSX2. No gsKit is used.

- Boot: `BOX3D_SAMPLE_START`, then `BOX3D_GS_READY` after CRT and double VRAM allocation.
- A native GS GIF frame clears the screen to dark navy and draws the ground
  grid, axes and moving box edges. No pixels are generated by `scr_printf`.
- The physics runner automatically cycles between Box Stack (12 boxes),
  Inclined Plane (5 boxes) and Spinning Books (3 boxes), every 600 frames.
- The packet encoder sends `GS_REG_FRAME_1/PRIM/RGBAQ/XYZ2` and related
  setup registers through GIF packed A+D on DMAC GIF channel 2; GS FINISH
  is waited before switching read-circuit framebuffer at VBlank.
- 320 x 224 pixel resolution, 2 x PSMCT32 framebuffer, no textures or
  Z-buffer in this first pass. Default physics mode is scalar C17.

This is an intentional subset of the desktop samples, not the full
Sokol/ImGui application. A correct physics log but black video usually
means GS initialization/GIF/coordinate setup needs fixing. First verify
the GS stage or provide a PCSX2 screen and the console log.

Source: `ps2/sample_native.c`, `ps2/gs_native.[ch]`.
PS2SDK APIs used for display-mode initialization: `graph_initialize`,
`graph_set_mode`, `graph_set_screen`, `graph_set_framebuffer`;
DMA: `dma_channel_initialize`, `dma_channel_send_normal`,
`dma_channel_wait`. Everything else in the rasterization pipeline
is low-level GS packet assembly.

**PCSX2 validation:** the tester provided a rendered screenshot of the
wireframe stacking sample on 2026-10-10 and reported it runs at 60fps.
This establishes real PS2 EE Box3D stepping plus native GS GIF wireframe
output on PCSX2, not performance of physical PS2 silicon.

## New optional GS filled triangles + hardware depth test

The build now also creates `ps2/box3d_ps2_samples_solid.elf`. It uses
the same Box3D physics sample runner but compiles the GS renderer with
`-DBOX3D_GS_SOLID=1`. The **previous** `box3d_ps2_samples.elf` remains
the regression-safe wireframe reference and is not silently replaced.

Solid mode allocates an additional aligned 320x224x32-bit Z buffer
using `graph_vram_allocate`, programs GS `ZBUF_1` and `TEST_1`
through raw GIF A+D, clears depth to zero per frame with a GS SPRITE,
then switches to `ZTST=GREATER_EQUAL` with higher Z assigned to nearer
vertices. Each non-ground cuboid sends 12 GS `PRIM=TRIANGLE` primitives
with a fixed directional ambient+diffuse color from its Box3D quaternion;
the ground grid and optional edges remain native GS lines. The renderer
waits for `GS_FINISH` and VBlank before swapping color buffers as
before. No gsKit, PS2SDK draw library, VU microcode, textures, or
C++/ImGui runtime is involved.

The first solid implementation does not do full near-plane triangle
clipping or perspective-correct depth interpolation; large or
camera-intersecting triangles may be rejected entirely. This is a
rendering bring-up, not a production mesh renderer.

**Status:** filled/Z-buffered GS ELF has not yet been crosscompiled
or executed in PCSX2. Verify separately from the already confirmed
wireframe screenshot; if solid fails, run the old
`ps2/box3d_ps2_samples.elf` and report logs/screenshots.

## Official-demo-inspired GS edition

In PCSX2 the tester confirmed `box3d_ps2_samples_solid.elf` produces
filled solids with correct Z occlusion. The new executable
`ps2/box3d_ps2_samples_official.elf` builds as an additional variant,
leaving both the previous wireframe and filled implementations intact.

The PC desktop sample uses a Preetham atmospheric sky, PBR/IBL materials,
sun shadows, GTAO, exposure/AgX tonemapping and an ImGui UI. The PS2
cannot run these graphics shaders in their current form, so this build
implements a carefully scoped low-cost GS approximation:

- A blue-to-hazy-daylight gradient sky using GS native Gouraud
  interpolated `PRIM=TRIANGLE` (IIP=1), without a texture.
- A pale, softly alternating checker ground of 12x12 two-triangle tiles,
  with discrete fine GS lines to resemble the official procedural grid.
- Opaque cuboids with muted daylight materials and directional face
  diffuse + ambient shading, maintaining original Box3D transforms.
- A projected planar shadow quad for every eligible cuboid,
  blended with `GS_SET_ALPHA` and depth writes disabled. This
  approximates but does not reproduce the original cascade shadow maps.
- A small semi-transparent sample-selection-style HUD on the left.
  The characters are a custom 5x7 bitmap emitted as raw GS sprites,
  with no IOP font service, gsKit, libdraw or textures.
- Hardware Z-testing, two PSMCT32 color buffers, the same physics
  stepping and scene switching as the confirmed working solid edition.

The draw packet grows from 2,048 to 8,192 quadwords in this edition
to cover the checker floor and GUI primitives. GS channel-2 DMA and
per-frame FINISH/VBlank synchronization remain unchanged.

```sh
git pull --ff-only origin experiment/ps2-ee-scalar
sh ps2/build_ee.sh
# Boot ps2/box3d_ps2_samples_official.elf in PCSX2
```

The scene fidelity is deliberately approximate: it does not support
image-based lighting, proper PBR BRDFs, arbitrary triangle near-clipping,
SSAO, real shadow maps, or ImGui. The displayed sample bodies are still
the simplified C17 ports, not byte-for-byte duplicates of every original
desktop scene. Some geometries may flicker or disappear near the camera,
and 60fps is unverified for this more expensive renderer.

**The official-inspired edition is new and not yet crossbuilt or
PCSX2-validated.** The previous GS-filled sample remains the fallback
if any rendering or performance regression occurs.
