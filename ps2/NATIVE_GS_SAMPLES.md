# Box3D PS2 visual sample bring-up: native GS + GIF

Run `sh ps2/build_ee.sh` with PS2DEV and PS2SDK installed. Start
`ps2/box3d_ps2_samples.elf` in PCSX2. No gsKit is used.

- Boot: `BOX3D_SAMPLE_START`, then `BOX3D_GS_READY` after CRT and double VRAM allocation.
- A native GS GIF frame clears the screen to dark navy and draws the ground
  grid, axes and moving box edges. No pixels are generated by `scr_printf`.
- The physics runner automatically cycles between Box Stack (12 boxes),
  Inclined Plane (5 boxes) and Spinning Books (3 boxes), every 600 frames.
- The packet encoder sends `GS_REG_FRAME_1/PRIM/RGBAQ/XYZ2` and related
  setup registers through GIF packed A+D on DMAC GIF channel 2; GS FINISH
  is waited before switching read-circuit framebuffer at VBlank.
- 320 x 224 pixel resolution, 2 x PSMCT32 framebuffer, no textures or
  Z-buffer in this first pass. Default physics mode is scalar C17.

This is an intentional subset of the desktop samples, not the full
Sokol/ImGui application. A correct physics log but black video usually
means GS initialization/GIF/coordinate setup needs fixing. First verify
the GS stage or provide a PCSX2 screen and the console log.

Source: `ps2/sample_native.c`, `ps2/gs_native.[ch]`.
PS2SDK APIs used for display-mode initialization: `graph_initialize`,
`graph_set_mode`, `graph_set_screen`, `graph_set_framebuffer`;
DMA: `dma_channel_initialize`, `dma_channel_send_normal`,
`dma_channel_wait`. Everything else in the rasterization pipeline
is low-level GS packet assembly.

**Crosslink and PCSX2 runtime for this new sample have not been tested
by the assistant**, because PS2DEV is unavailable in this environment.
